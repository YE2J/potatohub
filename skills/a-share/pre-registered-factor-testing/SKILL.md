# 预注册因子检验（可证伪的因子研究）

当一条因子/信号研究路径包含多个可量化的成败判定点时，**先冻结门槛再跑数据**。这套做法的价值不在结论好看，而在结论可信——**包括“证伪”**。适用于：把指标/盘感/形态移植为因子的可行性判定、多假设因子筛查、以及任何“跑完才知道行不行”的信号研究。

与设计类 skill 的分工：本 skill 管**判定协议与工程验收**（怎么判、判准了才归档），不管因子构思本身（见 quant-alpha-factory 的五步闭环）。

## When to Use

- 用户要验证一个“看起来有道理”的信号/指标是否真有 alpha
- 研究含多个假设（水平因子 / 背离 / 形态…），需分开判、分开归档
- 已知某类因子常被证伪，需预先防“把新因子证实成老因子的代理”
- 结论要交给独立方复核（本地 DB 对方够不到，需交可复算材料）

## 三条铁律（先写进设计稿，跑数据期间不得改）

1. **分层 gate 从便宜到贵**：覆盖率 → IC/单调性 → 月度同号稳定性 → **kill-switch（控制变量分层内单调 <3/5 ⇒ 判代理因子、直接终止）** → 成本/可交易性 → 事件研究。上游不过就不跑下游。
2. **预注册路径不偏离**：稀疏性（信号日覆盖 <1% 转连续变体）、相关性（|ρ(新因子, 已有因子)| > 0.4 转残差因子）、kill-switch 阈值——全部**事前写定**，禁止跑完看结果再选口径。分支要早在建因子时就把两条路都备好（如同时产出二元信号列 + 连续强度列）。
3. **停止条件预先写死**：“任一 gate 失败 ⇒ 如实写失败项、归档、**不复活、不反向、不调参、不换度量**”。否则一次干净的证伪会变成数据窥探。

## 两个必须带的反向对照

- **事件研究必带单因子对照**：背离/形态类信号必须同时报**控制短期反转（rev_20）后的净超额**，再加 FM 回归（行业固定效应 + rev_20 + 动量 + ln 市值）看符号是否存活。缺对照 ⇒ 结论不得归档为独立因子。
- **方向不对也是证伪**：预注册若要求“两组方向都成立”，就不要因为其中一组方向对而宣布成功。IC 显著为负也不等于“反向就是 alpha”——先过 kill-switch 查是不是被控变量的代理。
- 把“**不是代理**”与“**假设成立**”分两句报：控制后仍显著（排除代理）不等于方向符合假设。

## 假信号 warmup 掩码（下游一切检验的硬前置）

滚动窗口因子在数据起点附近会产出**窗口未满的定义外伪信号**。入表前加三重校验（序列索引 ≥ 最长窗+最短极值窗-1、价格窗满、水平极值窗满），并用断言验收：“数据起点后 N 个月内伪信号行数 == 0”。不修就跑结论，独立复核会直接打回。

## 负结果归档纪律

- **口径要写准**：数据只覆盖到某日就写“覆盖 A~B 共 N 日，其后 M 年整段空白”，不要写成“零散缺 N 日”——后者会被复核判为不诚实（实际是补采窗口根本没跑）。
- 负结果同样是成果：写清失败项 + 失败分类（**数据源假设类 / 工程类 / 纪律类**三类）+ 可复用资产（数据表、脚本、口径定义）+ 技术债。
- 归档时分「真缺陷 / 已知待补项 / 误判」，避免把后台进程中断写成设计失败。
- 先审“可交易性”再宣布可用：涨停买不进/跌停卖不出/停牌不可交易要在经济性层落地（需涨跌停价表 + 停牌表），属执行层约束，不改因子定义。

## 交付独立复核方的“三件套”

对方（如云端 Agent）访问不到本地 DB 时，光给结论无法验收。导出到双方共享目录：
1. **结果表全表 CSV**：`sqlite3 -header -csv <db> "SELECT * FROM <结果表>;" > 复核_<表名>.csv`
2. **关键分布计数**：分组计数、掩码前后异常计数、最早/最晚有效日、日覆盖率
3. **面板行数/交易日数 + 实际执行的 SQL 全文**（把 SQL 一并写进文本，对方才能逐字复算而不是猜你的分母）

先把材料同步过去再声称“已交付”，否则对方只能回“看不到、无法复核”。

## Pitfalls

- **上游 gate 没过就别碰下游**：IC 都不达标还去做经济性回测 = 用好看的数字淹掉已经成立的证伪。
- **“数据源不可得”要在能力层就承认**：免费/公开数据源的字段缺失（如只有主动单、无被动单）是真约束，不要用“转个方式实现”模糊化。目标应从“数值复刻”降级为“方向/信号复刻”并明写。
- **不要用临时脚本改口径**：改判定口径的权限在设计阶段，不在执行阶段。发现口径不适用时是暂停与重新预注册，不是就地调参。
