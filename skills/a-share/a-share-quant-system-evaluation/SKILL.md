# A股量化系统全维度评估框架

## 触发条件

当用户讨论以下话题时，加载本Skill：
- 评估量化系统方案或技术路线
- 审查现有系统的完整性和缺陷
- 讨论量化投资理念如何系统化落地
- 询问"我的系统还缺什么"、"这个想法可行吗"

## 核心理念

**IC方向 > 数据丰度** — 一个信号方向错误的系统，加再多数据也只会更准确地亏钱。评估的第一优先级永远是"信号是否统计显著"，而非"数据管道是否完善"。

## 评估架构：4-Agent 并行评估

当收到系统评估请求时，用 `delegate_task` 并行派发4个专业Agent。每个Agent独立的focus和评估框架：

### Agent 1：量化系统架构师
**评估维度**：技术可行性、性能、管线完整性

关注点：
- 数据层完整性（行情/资金/基本面/情绪覆盖度）
- 计算层效率（因子管线、增量/回填、幂等性）
- 存储层瓶颈（SQLite性能、索引、配置优化）
- 硬件资源（Mac Mini / 云服务器的负载预算）
- cron调度设计（链式依赖、错误传播、幂等）
- 技术风险矩阵（核心算法缺失、环境混乱、假错误）

典型发现模板：
```
SQLite优化：cache_size / mmap_size / temp_store
因子管线：核心算法实现状态、增量链路清晰度
资源评估：当前消耗 + 新增模块的CPU/内存预测
```

### Agent 2：策略分析师 / 金融研究员
**评估维度**：策略逻辑合理性、因子有效性、市场适配

关注点：
- 用户投资理念在A股是否成立（学术文献对照）
- 现有因子的IC/ICIR分项诊断（特别关注买入IC方向）
- 拟新增因子的选择逻辑和预期IC方向
- A股特殊制度的影响（T+1、涨跌停、散户结构、政策市）
- 买入信号IC为负的深度诊断（见下方模板）
- 因子拥挤度、过拟合风险
- 涨跌停不可交易对回测IC的偏误

**买入信号IC为负的诊断模板**：
```
1. IC窗口检查：T+1 vs T+5 vs T+10 不同窗口下的IC方向
2. 分市场状态：上涨市/震荡市/下跌市下IC是否一致
3. 涨停日过滤：排除涨停日的买入样本后IC是否改善
4. 散户共振：资金面买入信号是否与小单净流入同步
5. 窗口内反转：T日信号强但T+1~T+3反转（主力拉高出货）
6. 因子拥挤度：该信号是否已被大量策略同向使用
```

### Agent 3：量化系统产品经理
**评估维度**：用户需求匹配、迭代路线、产品价值

关注点：
- 用户当前阶段的真实需求（研究工具 vs 辅助决策 vs 半自主交易）
- 系统成熟度评估（数据/因子/策略/输出各层评分）
- MVP定义（最小可行产品应该是什么，不做清单）
- 分阶段迭代路线图（Phase 1/2/3）
- 每个Phase的交付物和验收标准
- 用户触点设计（每日推送/晨报/复盘报告）
- 成功标准定义（可量化的IC/Sharpe/胜率目标）
- 优先级排序矩阵（Impact × Urgency × Effort）

### Agent 4：风控与运维专家
**评估维度**：可靠性、错误传播、灾难恢复

关注点：
- 数据管线可靠性（单点故障、数据源中断）
- DB存储风险（SQLite单文件、碎片化）
- cron错误传播链（上游失败→下游空数据）
- 回测陷阱（未来函数、幸存者偏差、过拟合）
- 幂等性和错误恢复机制
- 数据备份策略
- 实盘前检查清单
- 因子计算checksum的一致性校验

## 工作流

1. **加载本Skill**：接到评估请求时，立即 `skill_view('a-share-quant-system-evaluation')`
2. **确认用户意图**：用 `clarify` 确认评估范围（全系统评估 vs 特定模块 vs 策略逻辑）
3. **派发4-Agent**：用 `delegate_task` 一次派发4个Agent（如果max_concurrent_children限制为3，先派3个再派1个）
4. **收集结果**：所有Agent完成后，读取完整报告
5. **合成输出**：将4份评估合并为结构化报告
6. **路线图**：提供分阶段实施建议，标记优先级的P0/P1/P2/P3

## Pitfalls

- **IC方向 > 数据丰度**：不要被用户"还缺什么数据"的提问带偏。先确认现有信号的IC方向，再谈新增数据源。
- **SQLite性能错觉**：不到50GB/千万行级别的SQLite无需迁移到PG/MySQL。先优化cache_size等PRAGMA。
- **cron假错误**：`cron_log_helper.sh` 等日志脚本的bug会导致cron报error但数据实际正常。检查脚本逻辑而非数据。
- **因子管线算法未实现**：factor_pipeline.py中可能标记了TODO。daily_factors表有数据不意味着因子计算链路完整。审查完整的计算链路。
- **T+1制度下的IC偏误**：使用T+1全天收益率做IC评估时，尾盘主力拉高出货模式的买入信号IC常常为负。建议改用T+1前30分钟收益率。
- **涨跌停不可成交**：买入信号在涨停时不可成交，卖出信号在跌停时不可成交。回测中必须剔除这些样本，否则IC高估实际收益。
- **因子拥挤度**：当多个因子相关性>0.7时，有效自由度下降，实际IC低于报告值。
