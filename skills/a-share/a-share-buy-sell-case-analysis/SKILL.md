# A股买入卖出点案例分析

## 触发条件

用户提供如下格式的案例数据：
- **股票代码 + 日期 + 买入/卖出点位**
- 标准格式：`{代码},{名称},{买入日期},{卖出日期},成为案例N`
- 单个日期格式：`{代码},{名称},{日期},收盘价和开盘价是多少?`
- 设定买入/卖出：`设定这个是买入点` / `作为买入卖出点的一个案例`
- 所有案例均以 **开盘价** 作为买入/卖出价格

## 分析流程（按序执行）

### ① 基础行情确认
- 通过 Tushare `daily` 接口获取该日期开盘/收盘/最高/最低/涨跌幅
- 确认该日期为有效交易日

### ② 现有因子检查
- 查询 `stock_data.db` 中的因子字段（技术面、基本面）
- 启动 `strategy_library/evaluation/ic_analyzer.py` 查看各因子IC表现
- 重点观察：MACD、KDJ、RSI、BOLL、VOL、主力资金等在该时间点的状态

### ③ 资金流分析
- Tushare `moneyflow_dc` 或 `moneyflow_ths` — 查看当日大单/中单/小单资金流向
- 主力资金净流入/流出情况
- 资金流向强度（净流入率）

### ④ 板块热度
- 同花顺/东财概念板块涨幅排名（`moneyflow_ind_dc` / `moneyflow_cnt_ths` / `ths_daily` / `dc_index`）
- 所属板块资金流入程度
- 该股在板块中的领涨/跟风位置

### ⑤ 公告与新闻
- Tushare 公告接口（`anns_d`）：检查业绩预告、增减持、重大合同等
- Tushare 快讯/新闻（`news` / `major_news`）：当日前后相关消息面驱动

### ⑥ 外部挖掘（可选）
- 搜索GitHub上类似策略的开源项目，借鉴因子思路
- 对比其他公开策略的信号规则

### ⑦ LLM 择时偏差审计（论文 2608.28399，RetailAgent）

> 依据：`RetailAgent: Structured Adverse Timing in Self-Conditioned Multimodal LLM Trading Agents`（arXiv 2608.28399，2026-08）。实验让 LLM 观察匿名化日内价格路径后逐段二选一（long=持仓 / flat=空仓），选完才揭示下一段收益，沿同一只股票的日内路径反复决策。样本为中盘指数 **CSI-500** 成分股的日内路径（239 分钟网格、每 stock-day 23 个 10 分钟决策区间），并向模型隐藏股票身份、日期、绝对价格、新闻、基本面与横截面排名。

**论文核心实证（引用时勿扩大范围）：**

1. **日内/短周期择时系统性为负**：在跨模态（文本/图表/图文）、决策周期（5/10/20 分钟）、账户状态、模型家族（Qwen3.5-9B 主实验；Claude Haiku 4.5、Granite 4.0 做符号核验）的 14 个标准配置中，股票内部择时全部为负——即 LLM 倾向于"在该股票随后的下跌段持仓、在上涨段空仓"。主实验 10 分钟文本条件 −45.7 bps/stock-day（13,710 个 stock-day）、仅图表 −29.9（14,937）、图文联合 −48.9（14,438）。
2. **打乱动作序列对照显著削弱该效应**：保持每只股票总多头占比不变、随机重排动作 → 全局打乱 −3.5 bps、同日打乱 −8.7 bps（对比原序列 −45.7）→ 负择时主要来自"动作与后续收益的序列对齐"，不是运气或市场整体方向。
3. **自述记忆会固化偏差**：把 1 条此前自写的记忆喂回决策上下文（w=0 → w=1），在含双向动作的 stock-day 上，择时从 −62.8 → −74.1 bps，日内换手从 2.5 → 1.7 次/日——切换更少，但更坚定地站在错的一侧。对照序列（把 long/flat 互换）按构造反转符号，用作符号诊断。
4. **正向总收益 ≠ 择时为正**：核心度量是 exposure-matched 股票内部择时 A = Σ_t(p_t − p̄)·r_t（p̄ 为该 stock-day 总多头占比，扣除"常年持仓吃贝塔"的假象）。分解式：多头累计收益 = p̄×全路径收益 + A。论文示例中多头区间收益 +359.4 bps、空仓区间 +1,404.0 bps、择时 −867.3 bps——"拿着能赚钱"与"在该拿的时候没拿"完全可以并存。

**审计步骤（何时做）：** 凡本框架分析结论中，由 LLM（本 agent 或子 agent）直接给出日内/短期（≤数日）方向判断——如"这里该买/该持有/该减"的语气评级、把 LLM 盘感叙述转成买入/持有依据、或用 LLM 自述理由支撑持仓决策——先过下列检验，再写入 🟢/🔴/🟡 三档输出。②③④ 步的客观因子/资金流证据不受此限。

1. **暴露匹配区间收益对比**：收集 ≥20 个 LLM 曾给出评级的案例窗口（个股+日期区间），评级动作编码 p_t（评级=多/持有 → 1；空/回避 → 0）；用 stock_data.db / Tushare 的日内或日线数据取每案例随后 N 个决策区间的收益 r_t（案例日可参考本 skill 的 ±3 交易日浮动规则放大样本）。计算 A = Σ_t(p_t − p̄)·r_t。**A 为负 → LLM 评级择时系统性错误，评级不可作为方向证据**；只有扣掉总体多仓占比后的对比才有效，直接比较"多头窗口平均收益 vs 空仓窗口平均收益"会混入暴露效应。
2. **打乱动作序列对照**：固定每个案例的多空占比，随机重排 p_t 时间戳 ≥1,000 次得零分布；真实 A 显著低于分布下沿（如 <2.5% 分位）→ 负择时来自"动作与后续收益的序列对齐"，是系统性结构而非噪声；落入分布中心 → 无方向性结构，评级近似随机择时。
3. **数据条件（如实报告）**：A 对纯多头/纯空头轨迹按构造记 0，只在"同一窗口内既有持有又有空仓"的样本上有定义——它测的是择时而非暴露。窗口内方向单一（如用户案例全是买入持有）时该案例不进审计样本，需标注"样本不含双向动作，无法测择时"。
4. **采信规则**：检验不过 → LLM 日内/短期评级降级为"信息整理/假设来源"，不得直接充当买入/卖出/持有信号，方向结论回到 ②③④ 的可量化证据。检验通过也只是"未发现负择时"，不等于"择时有效"——论文的对照度量只是单侧证伪工具。
5. **记忆固化警示（针对用户'拿不住'痛点）**：用户的痛点是换手过多；而论文显示喂回自述记忆会让 LLM **更少切换但更坚定地站在错侧**（w=1 时换手 2.5→1.7、择时更负）。因此**不要用 LLM 自述/复盘文字（"理由是…所以拿着"）作为持有信号依据**——自述会固化其既有（可能错误）观点。持有信号应绑定客观触发条件（主力资金是否仍在净流入、板块热度是否维持、是否触发止盈止损位），而非 LLM 的自我说服。

## 输出框架

每次分析结果按以下三档呈现：

| 维度 | 内容 |
|------|------|
| 🟢 **买入信号** | 什么因子/指标/事件触发了买入 |
| 🔴 **卖出信号** | 什么因子/指标/事件触发了卖出 |
| 🟡 **持有信号** | 什么条件下应继续持有 |

## 重要约束

### 买入/卖出日期浮动规则
- 每个案例的买入/卖出日期允许 **前后±3个交易日** 浮动，用于信号检测
- 因子信号可能在实际买卖日的前后3天内出现，不要死锁在单一日期
- 这对样本量有一定放大效果，降低了对精确日期的依赖

### 案例数据存储
- **不要自动保存到持久记忆（memory）** — 必须先询问用户存储位置：
  - 保存为 skill（适合长期参考的方法论）
  - 写入本地文件（如 `~/my_quant_system/案例/`）
  - 留在此会话聊天记录中（默认选项）
- 用户确认"就留在这个会话里"后，仅在会话上下文中保留，不写任何持久化存储

### 分析顺序
严格按照 基础→因子→资金流→板块→公告→外部的顺序，前面的维度有结论后再进入下一层，避免信息过载。

### 两阶段工作流

#### 阶段一：案例积累
- 先收集足够的买入/卖出案例（建议≥10个，理想≥20个）
- 案例数量不足时，派出 **3个Agent并行评估** 最低需要数量和推荐收集方向
- 每个Agent从不同角度（统计样本量、因子分析需求、行业扩展方向）给出建议
- 综合3个Agent意见后，确定目标案例数量，继续收集
- 排除约束：默认不收集 **科创板(688xxx)** 和 **北交所(8xxxxx)** 股票

#### 阶段一·五：探索性因子预研（6~15个案例时）
- 案例数不足20时，可做 **模式预研** 而非统计验证
- 用 `execute_code` 或 `delegate_task` 并行收集多只股票的 `moneyflow_dc` 资金流数据
- 观察买入点前20个交易日、卖出点前20个交易日的共性规律
- 输出为**定性观察报告**，用于指导后续因子挖掘方向，不做统计断言

#### 阶段二：因子挖掘
- 达到足够案例数量后，再考虑技术路线
- 使用IC分析框架评估各因子有效性
- 涉及的路线包括：技术面因子复现、资金流因子、板块轮动因子等

### 用户核心策略诉求（2026-07发现）

来自用户的明确表述：
1. **标的筛选**：找准当下**资金流入最多的板块的龙头股**作为交易标的
2. **操作维度**：不止买入卖出，还需要 **调仓信号、减仓信号、继续持仓信号**
3. **行为挑战**：用户交易过这些股票但"拿不住"——持有信号和仓位管理信号是关键痛点
4. **板块排除**：默认排除 **科创板(688xxx)** 和 **北交所(8xxxxx)**

## 预研数据批量收集技巧

当有多个案例需要同时分析时：
- 用 `mcp_tushareMcp_moneyflow_dc` 同时查询多只股票的买入/卖出日前20个交易日资金流
- 用 `mcp_tushareMcp_stk_factor_pro` 查询买入/卖出日前后的技术因子快照
- 观察到共性模式后，写入 `references/moneyflow-patterns.md` 作为模式库积累
