# 三方Agent评审摘要 (2026-06-21)

## 评审结论

GLM 5.2方案: 4.0/10 — 架构理念正确但代码完全不可落地
豆包方案: 5.6/10 — 架构更好但列表页URL是错的
融合方案: 取两者优点 + 创新，形成最终五层架构

## 两方案共同盲区(5个)

1. PDF解析链路缺失 — 证监会大量处罚书是PDF
2. 增量/全量双模式未区分
3. 异常处理/重试机制为零
4. 处罚类型未细分
5. 采集后质量校验缺失

## 最终采用

豆包(9项) + GLM(4项) + 创新(8项) = 完整方案

核心变化:
- 豆包的Hermes配置层(toolset+Skill+SOUL.md+cron) → 全部采用
- GLM的硬规则(is_detailed二分类) → 嵌入精筛层
- 创新: PDF解析、增量去重、质量校验、安全熔断
- 列表发现改用web_search替代Selenium(绕过Chrome依赖)
