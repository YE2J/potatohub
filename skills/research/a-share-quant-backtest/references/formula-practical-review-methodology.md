# 同花顺自定义指标/公式实战适用性审查方法论

审查目标：站在同花顺实盘用户角度，评估一个自定义副图/主图公式的**实战可用性**，包括信号质量、可操作性、视觉设计、计算正确性，并提出改进建议。

适用于任何用户给出的同花顺/通达信公式代码（KDJ、MACD变种、自定义信号等），不仅限于特定公式。

---

## 审查六个维度

### 1. 信号频率分析

用 stock_data.db 的 real data 跑信号计数，而不是靠感觉或读代码逻辑推断。

```python
# 核心思想：对一批股票（自选股或全A股），在一个时间窗口内统计买入/卖出信号次数
```

**操作步骤：**
1. 从 `daily_kline` 读取选定的股票池数据（按日期过滤，通常过去半年）
2. 用纯 Python 逐行实现公式的逐日逻辑（不依赖任何第三方指标库）
3. 在足够 warm-up 后（至少 20+ 个交易日），统计信号触发次数
4. 按 250 个交易日/年 年化

**给出范围**：不要只给均值，还要给最小值和最大值（有的股票一年0个信号，有的50+）。

**实战解读标准：**
- 0-6 个/年：偏保守，需要耐心等待，适合中长线
- 7-20 个/年：适中，月均1-2次，适合波段
- 20-50 个/年：偏多，周均1次，适合短线
- 50+ 个/年：过频繁，可能过度交易

### 2. 买入信号实战可操作性

重点检查**信号触发后次日能否实际买入**：

| 场景 | 风险等级 | 检查方法 |
|------|---------|---------|
| 信号出在涨停日 | 🔴 几乎不会发生 | 检查 J<0 时 pct_chg >= 9.5 的比例 |
| 信号出在跌停日 | 🟡 中风险 | 检查 J<0 当日是否跌停封板，跌停日的J值是否可信 |
| 信号出在无量空跌 | 🟡 中风险 | 检查信号日成交量 < 50% 均量 |
| 次日一字跌停无法买入 | 🟡 需过滤 | 检查次日开盘价 vs 当日收盘价 |

**方法论：**
- 对于每个买入信号日，检查该日的 `pct_change`（避免涨停）/ `volume`（避免无量）/ 次日的 `open` vs 当日 `close`
- 如果信号多来自跌停日，需要加成交量过滤器

### 3. 卖出信号的可靠性 — CROSS(100,J) 等高位触发

检查卖出信号是否会：
- **在强势股上根本不触发**（J值达不到100）
- **在高位震荡股上频繁进出**（J反复穿越100，导致反复买卖）

```python
# 检查 CROSS(100,J) 前一天的 J 实际值分布
# 检查卖出后多久又出现买入信号（短线循环）
```

**关键指标：**
- J 达到 100 的比例（很多强势股 J 只到 85-99）
- 卖出后 10 天内再次买入的次数（短线循环率）
- 卖出信号的 RSI(14) 对应值（辅助判断卖出点的有效性）

### 4. 公式计算正确性 — SMA/EMA 等关键函数的等价性

**这是最常见的坑。** 通达信/同花顺的 `SMA(X, N, M)` 与其他平台的实现可能不同。

| 函数 | 同花顺/通达信 | Python 等价实现 |
|------|-------------|---------------|
| `SMA(X, N, M)` | 首次值 = X；后续 = `(M×X + (N-M)×PREV)/N` | `ewm(alpha=M/N, adjust=False).mean()` — 当 M=1, N=3 时 `alpha=1/3` |
| `EMA(X, N)` | `(2×X + (N-1)×PREV)/(N+1)` | `ewm(span=N, adjust=False).mean()` |
| `MA(X, N)` | 简单移动平均 | `rolling(N).mean()` |
| `CROSS(A, B)` | A 上穿 B（上日 A≤B 且今日 A>B） | `prev_a <= prev_b and cur_a > cur_b` |
| `HHV(X, N)` / `LLV(X, N)` | N 日最高/最低 | `rolling(N).max()` / `rolling(N).min()` |

**关键陷阱：**
- `SMA(X, N)`（不带 M 参数）= 简单移动平均（MA），与 `SMA(X, N, 1)` 不同
- `SMA(RSV, 9, 3)` ≠ `RSV.rolling(9).mean()` — 这是最容易被混淆的
- 内置 KDJ 的 K 值 = `SMA(RSV, 3, 1)` = Python `ewm(alpha=1/3)`，**不是** `ewm(span=3)`（那等于 alpha=0.5）

**验证方法：** 对同一只股票，同花顺同时加载内置 KDJ 和自定义公式，K/D/J 三线应该完全重合。

### 5. 副图视觉设计评估

检查指标在副图中的**视觉拥挤度**，逐图层检查：

| 元素 | 评估要点 |
|------|---------|
| K/D/J 线 | 三条线颜色是否区分度好（白/黄/品红合理）|
| 参考线 (0/100) | 是否用虚线，颜色是否不刺眼 |
| 背景色 (DRAWBAND) | RGB 值是否柔和，透明度是否合适 |
| 信号箭头 | 是否每个信号日有箭头+柱+文字三重显示（冗余）|
| 文字标注 | `DRAWTEXT` 是否必要 |

**常见改进方向：**
- 去掉 `DRAWTEXT`（文字），保留 `DRAWICON`（箭头）+ `STICKLINE`（柱）即可
- 信号柱固定在某个位置（如 105），不随 J 值飘移
- 背景色 RGB 值降低饱和度（如从 `RGB(30,120,30)` 降到 `RGB(20,80,20)`）

### 6. 改进建议 — RSI 辅助等

基于实际数据提出**可量化的改进方案**：

**RSI 辅助卖出的分析方法：**
```python
# 统计 CROSS(100,J) 时 RSI(14) 的分布：
# RSI > 80 的比例？RSI > 70 的比例？平均 RSI？
```

**实战经验数据（本系统 KDJ 公式实测）：**
- CROSS(100,J) 时 RSI(14) > 80 仅占 ~24%
- 平均 RSI(14) = 68.2
- 说明仅用 CROSS(100,J) 错过大量顶部，因为 J 值在高位震荡趋势中难以达到 100

**三级卖出改进方案模板：**
```tonghuashun
{一级: 原卖出条件}
卖点1:=CROSS(100,J);

{二级: RSI超买确认}
RSI14:=RSI(CLOSE,14);
卖点2:=RSI14>80 AND CROSS(80,RSI14);

{三级: J高位+RSI共振}
卖点3:=J>80 AND RSI14>70 AND J<REF(J,1) AND REF(J,1)>REF(J,2);

{最终}
卖点:卖点1 OR 卖点2 OR (卖点3 AND MA5<MA10);
```
