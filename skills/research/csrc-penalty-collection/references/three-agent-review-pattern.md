# 三方 Agent 并行评审模式

本会话两次使用了该模式，验证有效。

## 模式

```
用户抛出问题/方案 → Agent 1（角度A）+ Agent 2（角度B）+ Agent 3（对比/融合）
                   ↓ 并行执行
              汇总三方结果 → 用户决策 → 执行
```

## 本会话实战案例

### 案例 1：GLM vs 豆包方案评审

三个 Agent 分别：
- Agent 1：深度评估 GLM 5.2 方案（5维打分 + 优缺点）
- Agent 2：深度评估豆包方案（5维打分 + 优缺点 + **实地验证 URL**）
- Agent 3：对比融合 + 找盲区 + 出融合方案

关键发现：Agent 2 独立验证了豆包的 URL 是错的 → 避免了后续所有工作基于错误假设。

### 案例 2：技术方案设计

三个 Agent 分别：
- Agent 0：反爬安全架构（超时，但任务分配正确）
- Agent 1：数据质量筛选规则引擎
- Agent 2：存储与分析管线（**已直接建好数据库**）

## 分配原则

| Agent | 角色 | 典型任务 |
|-------|------|----------|
| A | 方案A评审 / 维度1 | 深挖一个方案的优劣 |
| B | 方案B评审 / 维度2 | 交叉验证，发现对方盲区 |
| C | 对比融合 / 创新 | 取长补短，提新思路 |

## 适用范围

- 评估多个 AI 生成的方案
- 复杂系统的多维度设计（反爬 + 筛选 + 存储）
- 需要交叉验证的研究任务
