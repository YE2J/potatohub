# arXiv API 语义笔记 + 2026-09-04 静默漏检事故复盘

## arXiv API 关键语义（2026-09-04 实测）

### 公告节奏
- arXiv 每日约 **20:00 UTC**（北京 04:00）发布当日公告批次。
- API 可检索时刻滞后于提交：论文提交后进入「次日公告批」，公告后才出现在查询结果中；`published` 字段 ≈ 提交时刻（公告日 12:00–19:00 UTC 区间提交的常见）。
- 推论：北京时间 03:xx（UTC 前一日 19:xx）运行的查询，**看不到当天 20:00 UTC 公告批**——早于公告约 50 分钟。

### 排序与容量（证伪"修订版挤占"假说）
- `sortBy=submittedDate` 返回的 top-200 覆盖约一个月（实测 2026-08-02~09-03，32 天 200 篇）。
- 修订版（`updated != published`）占比仅 10%（20/200）。q-fin.* 全子类日产量 1~12 篇。
- 结论：top-200 容量充足，漏检不是排序挤占，而是**查询窗口/时刻与公告错配**。

### 日期范围查询（官方推荐，修复方案）
```
https://export.arxiv.org/api/query?search_query=cat:q-fin.*+AND+submittedDate:[202609031200+TO+202609051505]&start=0&max_results=500
```
- 时间格式 `YYYYMMDDHHMM`（UTC）；与 cat 组合用 `AND`。
- 返回条数按 published 分布可用作诊断：dump 各日期条数即可看出公告批次分布。
- 本地二次过滤只做下界校验（防语法回退返回全量），不做滚动窗口。

### 诊断证据链（复现路径）
1. `tail ~/.logs/arxiv_qfin.log`：08-24~09-03 全部「API 返回 200 条, 24h 窗口内 0 条」——API 可达，非网络。
2. 同款查询 dump top-200：published 覆盖 08-02~09-03；修订 10%；24h 窗口内仅 1 条（当时 07:00 UTC）。
3. 对照运行时刻 03:10 CST=前日 19:10 UTC → 比 20:00 UTC 公告早 50 分钟 → 窗口上沿切掉当天公告批；"昨天公告批"中 submitted 早于窗口下沿的也被切 → 窗口恒 0。
4. 佐证：72h 窗口那次（08-23 22:50）抓到论文；改 24h 后连续 0。

### 修复三件套（已验证）
1. **查询**：`submittedDate:[起 TO 止]` 日期范围，服务端过滤。
2. **时刻**：cron 改每周六 02:00 CST（公告后，窗口天然覆盖整周）。
3. **容错**：网络层错误退避重试 60s/300s/900s ×3（URLError/OSError/Timeout；HTTPError 立即失败）；保留 `ARXIV_SINCE_DAYS`/`ARXIV_SINCE_DATE` 覆盖。
