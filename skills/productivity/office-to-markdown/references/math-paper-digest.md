# 数学论文 / 定理型预印本结构化消化

适用：上传的 PDF 是长数学论文（arXiv/预印本/期刊，几十~数百页，大量编号定理），
全量逐字读不可行（实测 166 页 ≈ 590K 字符 ≈ 15 万 token）。本文件是「全量分析模式」
下对定理密集文档的可行路径，产出结构化 digest 而非逐字理解。

## 流程（按序）

1. **全文本地提取**（pymupdf 逐页 `<!-- PAGE N -->`，见 SKILL 主文件）→ `wc -l -w -c` 量级判断。
2. **身份识别**：读第 1–2 页标题/作者/摘要 + PDF meta（creationDate、creator=LaTeX）。
   pdfTeX + 近一两天的日期 → 刚发布的预印本，报道口径要特别保守。
3. **定理地图**：`grep -nE "^(Theorem|Proposition|Corollary|Lemma|Definition|Remark) [0-9]"`
   拿到全部编号结果 → 分清主定理（引论）、技术核心（正文中段常是证明心脏）、收尾推论、
   附录技术引理，形成论文骨架再决定抽样。
4. **必读切片**（其余按需）：① 引论主定理陈述**逐字**（含每个假设与结论）+历史背景；
   ② 技术核心定理陈述（如「残差各阶平坦性」类）；③ 结尾 Corollary/应用结果；④ 参考文献表。
5. **机制段**（标题如 Physical description / Proof outline）用大白话重述构造思想。
6. **范围核查**：重大结果核实「主张覆盖的问题变体」——外力 vs 无外力、周期 vs 全空间、
   耗散阶是否完整。报告写清触及/未触及哪些官方备选项（例：Fefferman 千禧年表述 (A)/(B)
   无外力 vs (C)/(D) 带外力），勿把带外力版说成原问题已解决。
7. **外部核实（惊人主张必做）**：web_search 论文题/机构作者 → MathOverflow/arXiv/官方
   声明核实三层事实并分开陈述：① 论文是否真实存在 ② 是否经独立验证 ③ 来源/同日竞争争议。
8. **内部一致性抽查 ≠ 正确性**：论文自报标度/幂指数关系用 sympy 程序化复算
   （E ∝ τ^{a+b} 代数自洽、积分收敛条件如 h<1/6）。通过只说明「内部代数自洽」，
   报告必须显式写「⚠️ 证明正确性无法在此验证，需同行逐行核查」，不得暗示背书。
9. 报告表格优先，结论要点单列「已解决/未解决/验证状态」三列。

## 陷阱

- 摘要/引言中的「声称」不是「已证事实」；呈现时区分 声称 / 独立验证状态 / 来源争议。
- 引用论文公式前意识到文本层上下标会断行错乱——关键公式核对以原 PDF 为准。
- LaTeX 论文图常为矢量（0 张位图），勿为图注数量启动 vision（见 SKILL 主文件 Pitfalls）。
- 报告标注取样范围（如「TOC+定理地图+关键章节抽样」），不冒充通读全篇。
- 涉及新设文档库分类时走主文件类型表规则（声明默认 + 用户未反对即确认）。
