# 聚合模型纪律：参考模型会基于乱码/幻觉捏造"严重 bug"（2026-08-24 实测）

## 场景

MOA 评审 wiki 优化任务时，多个参考模型的工具输出出现大量乱码/异常，它们随即基于这些乱码**自信地报告一堆"严重 bug"**：
- "index.md 严重损坏"（minimax）
- "切片文件全是 `---`"（deepseek）
- "估值 _latest 停在 5 天前/08-19"（minimax）

## 实际真相（聚合者用真实工具独立验证）

- `grep -rl $'\ufffd' ~/.hermes/wiki` → **0 命中**（U+FFFD 替换符是文件级真乱码的唯一硬判据）
- index.md 39 行完好；切片 frontmatter（title/created/updated）齐全；三个 `_latest.md` 与最新切片 `diff -q` 全部一致
- 唯一真实发现（非乱码）：根目录孤儿文件 + 日报归档 127KB 超标——是旧 cron 写错路径的历史残留，与"乱码"无关

## 铁律

1. 参考模型的"发现"是**自报，不是事实**。它自己的工具输出乱码/截断时，它的结论大概率是幻觉
2. 每个声称的 bug 先用真实工具独立验证（`read_file`/`diff`/`grep`/`ls`），验证命令要能复现，再写入结论
3. 区分"真乱码"来源：文件级真损坏的唯一硬判据是 U+FFFD 替换符（`grep -rl $'\ufffd' <path>`）；JSON `\uXXXX` 转义、`[TRUNCATED]` 截断标记、emoji 变体选择符安全告警都是**显示层噪声，不是数据乱码**
4. 多模型同时报同一 bug ≠ 真实：若共同点只是"都读了同一份乱码输入"，会集体幻觉。只有真实工具输出能背书
